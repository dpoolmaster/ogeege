## 2. Аутентификация и сессия

- Вход через `id.umschool.net` (SSO), токены access/refresh.
- Access-токен передаётся в API (`Authorization: Bearer ...`), refresh — через `/api/v3/auth/refresh/`.
- Bridge-токены: `auth-bridge.umschool.net` (localStorage `access_token`, `refresh_token`), fallback в `nd` (`UMSCHOOL-BRIDGE-TOKENS-FALLBACK`).
- При отсутствии/истечении токена — редирект на `/login?redirect=...`.
- OAuth-клиент: `client_id=9VzxpopERpimczRNQrUAWiRURUzzThgHd1Wx0WzO`, `client_redirect=https://nd.umschool.net/oauth-callback`.

## 5. Права ученика (наблюдаемые)

### Данные
- Видит только свой профиль, свои ДЗ, свои занятия, свою корзину, свои подписки, свои достижения.
- Не видит чужие данные; API возвращает 401/404 при отсутствии доступа.
- Может просматривать публичные документы и общие материалы.

### Действия
- Создавать/редактировать: ответы ДЗ, ник, push-настройки, цели, корзину, промокод, реферальную ссылку.
- Не может: менять e-mail (только через поддержку), удалять аккаунт через UI, управлять курсами/уроками, проверять ДЗ, менять оценки.
- Может отказаться от ДЗ, запросить доп. проверку, оценить ДЗ/занятие.

### Финансы
- Может добавлять/удалять товары, применять промокод, переходить к оплате, оплачивать по ссылке.
- Не может менять цены, тарифы, начислять бонусы.
- Управление автопродлением/способами оплаты — при наличии подписки (не проверено).

### Коммуникации
- Может писать куратору (при наличии предмета/диалога), в поддержку, в чат сайта.
- Может настраивать push.
- Не может рассылать массовые сообщения.

## 7. Ограничения аккаунта и исследования

1. Один аккаунт `STUDENT_ROLE`, без покупок, с одним бесплатным демо-курсом.
2. Нет родительского/кураторского/админского доступа.
3. Нет активной подписки → нельзя проверить права на продление/оплату.
4. Нет диалогов → нельзя проверить права чата.
5. Публичная регистрация проверена только частично (валидация телефона/почты).

## 8. Рекомендации по реализации RBAC

- Роли: `guest`, `student`, `parent` (опционально), `curator`, `teacher`, `manager`, `admin`, `support`, `pay_inspector`.
- Права на уровне ресурсов: `owner_id`, `product_access`, `role`.
- Проверки:
  - доступ к продукту/уроку — по факту покупки/выдачи;
  - доступ к ДЗ — по `submission.user_id`;
  - доступ к корзине — по `hash`/owner;
  - доступ к чату — по участнику топика;
  - админские операции — по роли + audit log.
- Не полагаться только на скрытие UI: серверная авторизация обязательна.
- Для родителя — отдельная связь `parent_student` и read-only доступ к прогрессу/оплатам (в исходном продукте не подтверждено).
