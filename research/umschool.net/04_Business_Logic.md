# 04. Бизнес-логика

Правила сгруппированы по доменам. Для каждого указаны триггер, условия, действие, результат, исключения, источник и уверенность.
Источники: `UI` — наблюдаемый интерфейс, `API` — ответы сервера, `CODE` — frontend-бандл/локаль, `INFERRED` — вывод.

---

## 1. Аутентификация и доступ

### BL-AUTH-01. Валидация телефона по стране
- **Триггер:** ввод номера на `/login`.
- **Условия:** выбрана страна Россия / Беларусь / Казахстан.
- **Действие:** клиентская маска и проверка длины.
- **Результат:** при неверном номере — «Некорректно указан номер».
- **Исключения:** пустой номер, `+7` без цифр.
- **Источник:** UI. **Уверенность:** CONFIRMED.

### BL-AUTH-02. Пароль
- **Условие:** смена пароля.
- **Правило:** минимум 6 символов; повтор должен совпадать («Пароли не совпадают»).
- **Источник:** UI (`change-password`, локаль). **Уверенность:** CONFIRMED.

### BL-AUTH-03. E-mail-вход
- **Условие:** вход по почте.
- **Правило:** требуются и почта, и пароль; при неверной паре — «Невозможно войти с предоставленными учетными данными.»
- **Источник:** UI/API. **Уверенность:** CONFIRMED.

### BL-AUTH-04. Защита маршрутов
- **Правило:** все маршруты `nd.umschool.net`, кроме `/login`, `/cart-owned-by-another`, `/switch/na`, `/forbidden` и error-страниц, требуют роль `STUDENT_ROLE`; иначе редирект на `/login?redirect=...`.
- **Источник:** CODE (meta.roles), UI. **Уверенность:** CONFIRMED.

### BL-AUTH-05. Токены
- **Наблюдение:** `id` access token TTL ≈ 15 минут, refresh ≈ 120 дней; `nd` fallback access TTL ≈ 14 дней, refresh ≈ 30 дней.
- **Правило:** access обновляется через `/api/v3/auth/refresh/`; bridge хранит токены в `auth-bridge.umschool.net`, fallback — `UMSCHOOL-BRIDGE-TOKENS-FALLBACK` в localStorage `nd`.
- **Источник:** JWT/CODE. **Уверенность:** CONFIRMED (сроки), INFERRED (refresh-логика).

### BL-AUTH-06. VK ID
- **Правило:** VK ID используется как альтернативный вход; привязка VK из профиля открывает OAuth.
- **Источник:** UI. **Уверенность:** CONFIRMED (кнопка).

## 3. Каталог, продукты, цены

### BL-CAT-01. Типы курсов
- **Коды:** `SUMMER_COURSE`, `PB` (Предбанник), `FLASH` (Бустер), `MIDDLE` (Средняя школа), `OLIMP`, `MG` (Курсы за другие года), `DEMO`, `RULETKA` (ДВИ), `COURSE` (Доп. курсы), `IND` (Индивидуальные), `WINTER_COURSE`, `SPRING_COURSE`, `MG_NEXT` (Ноябрьский поток).
- **Источник:** API `sys-course-types`. **Уверенность:** CONFIRMED.

### BL-CAT-02. Структура цены
- **Правило:** цена продукта = цена тарифа за выбранный месяц/период; на карточке — «от N ₽»; при наличии скидки `oldPrice > price`.
- **Пример:** История 7 класс: Стандарт 4 990 ₽, Про 5 990 ₽, Премиум 7 090 ₽ (декабрь 2026).
- **Источник:** API `rate-plans`. **Уверенность:** CONFIRMED.

### BL-CAT-03. Тарифы
- **Тарифы:** Стандарт (самостоятельная работа), Про (куратор, углублённые темы, мини-тесты), Премиум (всё из Про + групповые консультации и контрольные).
- **Фичи:** 20+ ключей (`has_personal_curator`, `has_webinars`, `has_homeworks`, `faster_points`, `control_work`, `ind_homework`, `has_statistika`, `help_with_hw`, `wor_exam_vpr`, `group_consultations`, `personal_meet_1/2`, `note_topic`, `english_speaking_clubs` и др.).
- **Источник:** API `core/features`, `rate-plans`. **Уверенность:** CONFIRMED.

### BL-CAT-04. Скидки каталога
- **Правило:** процент скидки приходит в `payment.percentDiscount`; на публичном сайте — «комплекты со скидкой до 30%», в LMS-баннере — «до 60%» при сборке комплекта из 2–4 предметов.
- **Расхождение:** 30% vs 60% — разные механики/периоды; зафиксировано как есть.
- **Источник:** UI. **Уверенность:** CONFIRMED (тексты), INFERRED (применение).

### BL-CAT-05. Комплект
- **Правило:** выбор 2–4 предметов (баннер LMS) или 2–8 (конфигуратор MIDDLE); скидка зависит от количества и срока.
- **Шаг 2:** преподаватель на каждый курс, срок (1 мес / год / 2 года), тариф.
- **Источник:** UI. **Уверенность:** CONFIRMED (UI), INFERRED (точная формула скидки).

### BL-CAT-06. Каталог: фильтры
- **Фильтры:** классы, предметы, преподаватели, язык; на публичном сайте — «Курсы, Классы, Предметы, Цели, Преподаватели».
- **Источник:** UI/API. **Уверенность:** CONFIRMED.

### BL-CAT-07. Доступность продукта
- **Правило:** API `products/types/for-catalog` возвращает только доступные к покупке продукты (115 на дату исследования); часть курсов может быть `purchased=true` и недоступна повторно.
- **Источник:** API. **Уверенность:** CONFIRMED.

## 4. Корзина, промокоды, реферальная скидка

### BL-CART-01. Один товар — один продукт
- **Правило:** повторное добавление продукта → «Продукт уже в корзине»; при конфликте комплекта — «Нужно освободить корзину для добавления нового продукта».
- **Источник:** CODE/UI. **Уверенность:** CONFIRMED (строки).

### BL-CART-02. Специальная цена / optional gift
- **Правило:** при добавлении декабрьского продукта автоматически предлагается/добавляется ноябрьский продукт со скидкой (например, 4 990 → 3 000 ₽), отображается как «Специальная цена при покупке курса».
- **API:** `optional_gifts[]` c `cart_item_id`, `price`, `initial_price`.
- **Источник:** API/UI. **Уверенность:** CONFIRMED.

### BL-CART-03. Промокод
- **Правило:** одновременно можно использовать только один промокод; промокоды не суммируются; нельзя совмещать с реферальной скидкой.
- **Ошибка:** «Некорректный промокод.»
- **Источник:** UI/CODE. **Уверенность:** CONFIRMED.

### BL-CART-04. Реферальная скидка
- **Правило:** скидка по реферальной программе отображается в корзине; при её наличии промокод требует отключения скидки.
- **Источник:** CODE. **Уверенность:** CONFIRMED (текст).

### BL-CART-05. Владение корзиной
- **Правило:** корзина имеет `hash`; можно поделиться ссылкой `/cart-owned-by-another?hash=...`; оплата чужой корзины — «Вы оплачиваете корзину для пользователя».
- **Источник:** API/UI. **Уверенность:** CONFIRMED.

### BL-CART-06. Очистка
- **Действие:** `POST /api/v2/cart/clear/` очищает все позиции, подарки и купоны.
- **Источник:** API. **Уверенность:** CONFIRMED.

### BL-CART-07. Суммы
- **Правило:** `amount = сумма позиций − скидки`; `initial_amount` — без скидок; `amount_description` — пояснение.
- **Пример:** 4 990 + 3 000 = 7 990 при `initial_amount` 9 980 и скидке −1 990.
- **Источник:** API/UI. **Уверенность:** CONFIRMED.

## 5. Оплата и подписки

### BL-PAY-01. Способы оплаты и скидки
- **Способы:** СБП (−20%), банковская карта (−20%), рассрочка (−18%), Яндекс Сплит (−20%), T-Pay (−20%), Яндекс Пэй (−20%), по реквизитам для физлиц (−20%), цифровой рубль (−20%), по реквизитам для юрлиц/ИП (−20%).
- **Правило:** скидка за способ оплаты вычитается из суммы заказа.
- **Источник:** checkout UI. **Уверенность:** CONFIRMED (наблюдаемые проценты).

### BL-PAY-02. Рассрочка
- **Условия (публичная страница):** сумма > 5 000 ₽; 3/6/12 месяцев; гражданство РФ; возраст 18–70; для Сбербанка — дебетовая карта и СМС-оповещение; решение принимает банк; единая рассрочка на несколько продуктов.
- **Источник:** `/sposoby-oplaty/`. **Уверенность:** CONFIRMED.

### BL-PAY-03. Оплата по реквизитам
- **Правило:** QR или ручной ввод реквизитов; прикрепить чек; «В течение 30 минут чек будет проверен и мы откроем доступ».
- **Источник:** UI/локаль. **Уверенность:** CONFIRMED (текст).

### BL-PAY-04. Ссылка на оплату
- **Правило:** корзину можно оплатить по ссылке (`/cart-owned-by-another?hash=...`), ссылка копируется; оплата другого пользователя допустима.
- **Источник:** UI/API. **Уверенность:** CONFIRMED.

### BL-PAY-05. Завершение оплаты
- **Правило:** после успешной оплаты доступ к продуктам открывается автоматически; редирект на `/payment/success/:transactionUuid`.
- **Источник:** CODE/локаль. **Уверенность:** OBSERVED.

### BL-SUB-01. Подписка и автопродление
- **Правило:** списание по подпискам автоматическое; отключить можно в любой момент в личном кабинете; после отключения доступ сохраняется до конца оплаченного периода, затем преимущества теряются.
- **Источник:** UI/локаль. **Уверенность:** CONFIRMED (тексты), NOT_TESTED (фактическое списание).

### BL-SUB-02. Причины отключения автопродления
- **Справочник:** `manual_payment` («Предпочитаю оплачивать вручную»), `bad_date` («Не подходит дата списания»), `low_progress` («Не ощущаю прогресс»), `not_ready` («Сейчас не готов(а) продолжать учёбу»), `bad_fit` («Не совпал формат/темп»), `other` («Другое»).
- **Источник:** API. **Уверенность:** CONFIRMED.

### BL-SUB-03. Продление/улучшение
- **Правило:** ручное продление и апгрейд тарифа доступны в `/subscriptions`. «Этот месяц уже входит в твою подписку» — повторное продление того же месяца блокируется.
- **Источник:** UI/локаль. **Уверенность:** OBSERVED/INFERRED.

### BL-SUB-04. Привязка карты
- **Правило:** карта привязывается для автопродления; «Карта подключится после ручного продления», «Сейчас карта не привязана».
- **Источник:** локаль. **Уверенность:** OBSERVED.

### BL-SUB-05. Распределение стоимости
- **Правило:** «Стоимость годовой программы распределяется таким образом, что скидка применяется на последние месяцы».
- **Источник:** cart UI. **Уверенность:** CONFIRMED.

## 7. Домашние работы

### BL-HW-01. Шкала баллов
- **Правило:** баллы считаются в процентах; полностью верные задания базового уровня = 100 баллов (100%); задания со звёздочкой дают ещё +100% (дополнительно).
- **Источник:** локаль `how_homework_points_calculated`. **Уверенность:** CONFIRMED (текст).

### BL-HW-02. Дедлайн
- **Правило:** после дедлайна ДЗ можно сдать/отредактировать, но куратор его не проверит. Найти ДЗ после дедлайна можно в списке с фильтром «Отказ».
- **Источник:** локаль. **Уверенность:** CONFIRMED (текст).

### BL-HW-03. Таймер
- **Правило:** на ДЗ может быть таймер; по истечении времени работа автоматически отправляется на проверку. Отвлечение не останавливает таймер.
- **Источник:** локаль. **Уверенность:** OBSERVED/INFERRED.

### BL-HW-04. Статусы проверки
- **Enum:** `UNDONE`, `DONE`, `REFUSED`, `RESENT`, `CHECKED`, `EXPIRED`, `RECHECKED`, `CHECKED_BY_SITE`, `CHECKED_BY_CURATOR`, `CHECKED_BY_TEACHER`, `CHECKED_BY_NEURO`, `CHECK_BY_NE_AND_CU`.
- **Правило:** автопроверка тестов, проверка куратором/Умкой (AI), возможность запроса доп. проверки.
- **Источник:** CODE/API. **Уверенность:** CONFIRMED (enum), INFERRED (переходы).

### BL-HW-05. Работа над ошибками
- **Правило:** после каждого выполнения ДЗ создаётся работа над ошибками на похожих заданиях; доступна, если `work_on_mistakes_available=true`.
- **Источник:** API/локаль. **Уверенность:** CONFIRMED.

### BL-HW-06. Пустой ответ
- **Правило:** нельзя отправить пустой ответ; нужно выбрать «Пропустить».
- **Источник:** UI. **Уверенность:** CONFIRMED.

### BL-HW-07. Повторное выполнение
- **Правило:** если по теме есть начатое ДЗ, система предлагает продолжить или создать новое («По этой теме уже есть начатое ДЗ»).
- **Источник:** локаль. **Уверенность:** OBSERVED.

### BL-HW-08. Типы проверки
- **Правило:** `AUTO` — автопроверка, `NO_CHECK` — без проверки (текстовые опросы), `CURATOR` — ручная; правильные ответы и решения могут скрываться до проверки.
- **Источник:** API `check_type`, локаль. **Уверенность:** CONFIRMED.

## 8. Тренажёр и аналитика

### BL-TRAIN-01. Режимы
- **Правило:** «Карточки» — лёгкий режим для быстрого повторения; «Заучивание» — сложный для запоминания.
- **Источник:** UI. **Уверенность:** CONFIRMED.

### BL-TRAIN-02. Статусы карточек
- **Правило:** Новое → Изучаю → Знаю → Повторяю (интервальное повторение); «Новое» появляются впервые, «Знаю» показываются реже, «Повторяю» — освоенные, но давно не повторявшиеся.
- **Источник:** локаль. **Уверенность:** CONFIRMED (описание), OBSERVED (переход).

### BL-TRAIN-03. Ограничения
- **Правило:** можно выбрать время тренировки (без ограничений / минуты) и количество карточек (до максимума); «Можно выбрать максимум {n} карточек».
- **Источник:** UI/локаль. **Уверенность:** CONFIRMED (UI).

### BL-TRAIN-04. Оценка карточки
- **Правило:** «Не знаю» / «Знаю»; обе оценки отправляют правильный ответ и переходят к следующей карточке; счётчики обновляются.
- **Наблюдение:** после «Знаю» карточка попала в «Изучаю». Возможен баг или особенность алгоритма.
- **Источник:** UI/API. **Уверенность:** CONFIRMED (наблюдение).

### BL-TRAIN-05. Награда
- **Правило:** завершение тренировки начисляет 50 ОП (наблюдаемо; API `finish` вернул `exp:0`, итоговый профиль — 50 ОП). Возможна отдельная асинхронная выдача опыта.
- **Источник:** UI/API. **Уверенность:** CONFIRMED (расхождение зафиксировано).

### BL-TRAIN-06. Уровень знаний
- **Правило:** ИИ оценивает уровень знаний по решённым заданиям; без данных — «Не хватает данных для оценки».
- **Источник:** локаль. **Уверенность:** INFERRED.

### BL-TRAIN-07. Предсказание балла
- **Правило:** прогноз строится по баллам последнего пробника; без пробников — 0.
- **Источник:** API `umits/class-types/:id/info/`. **Уверенность:** CONFIRMED (значение), INFERRED (модель).
