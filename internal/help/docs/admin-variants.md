# Варианты

Раздел «Варианты» собирает готовые наборы заданий для диагностики, тематической практики и пробников. Вариант — это заголовок, назначение, длительность и упорядоченный список заданий с баллами. Ученик проходит вариант по серверному таймеру, поэтому длительность задаётся в минутах.

Вариант не создаёт задания и не меняет их. Он только ссылается на уже существующие задания банка. Поэтому сначала наполните раздел «Задания», а затем собирайте варианты.

## Где используется вариант

| Место | Что берётся из варианта |
|---|---|
| Диагностика | Набор заданий и длительность; по результатам строится карта пробелов. |
| Тематическая практика | Набор заданий для отработки темы. |
| Пробник | Полный набор заданий, имитирующий реальный экзамен, и серверный таймер. |
| Статистика и прогноз | Первичный балл считается по баллам заданий варианта и шкале перевода. |

## Виды вариантов

| `kind` | Название в интерфейсе | Назначение |
|---|---|---|
| `diagnostic` | Диагностика | Входная проверка уровня ученика. |
| `practice` | Практика | Отработка темы или группы заданий. |
| `mock` | Пробник | Полный экзаменационный вариант с таймером. |

Вид влияет на то, как вариант показывается ученику и в каких сценариях используется. Он не меняет состав заданий и не проверяется при публикации.

## Статусы

| Статус | Что означает | Видят ли ученики |
|---|---|---|
| `draft` | Черновик. Собран, но ещё не опубликован. | Нет |
| `published` | Опубликован. Доступен ученикам. | Да |
| `archived` | Архив. Зарезервирован в схеме, но через интерфейс не выставляется. | Нет |

Через интерфейс вариант можно только создать и опубликовать. Редактирования, удаления и архивирования варианта в текущей версии нет: если состав нужно изменить, соберите новый вариант. Опубликованный вариант нельзя пересобрать — создайте новый.

## Поля варианта

| Поле | Обязательно | Что указывать |
|---|---|---|
| **ID учебного года** | Да | UUID учебного года. Все задания варианта должны относиться к этому году. |
| **Название** | Да | Отображаемое название, например «Пробник №1». |
| **Вид** | Да | `diagnostic`, `practice` или `mock`. |
| **Минуты** | Да | Длительность прохождения. Должна быть больше нуля. Используется серверным таймером. |
| **Задания вручную** | Для ручной сборки | JSON-массив `{"task_id":"...","points":1}`. |
| **Правила генерации** | Для генерации | JSON-массив `{"kim_number_id":"...","count":1,"difficulty":"easy","topic_id":null}`. |

Все идентификаторы — UUID. В таблице вариантов ID не выводится; он возвращается API при создании и в списке.

## Ручная сборка

Ручная сборка используется, когда состав варианта известен заранее.

1. Заполните ID учебного года, название, вид и длительность.
2. В поле «Задания вручную» вставьте JSON-массив:

```json
[
  {"task_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abc", "points": 1},
  {"task_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abd", "points": 2}
]
```

3. Нажмите «Создать вручную».

Правила:

- массив не должен быть пустым;
- задания не должны повторяться в одном варианте;
- каждое задание должно существовать и принадлежать выбранному учебному году;
- баллы — целые неотрицательные числа;
- позиции заданий в варианте выставляются по порядку элементов массива, начиная с 1.

Баллы в ручной сборке не сверяются с максимальным баллом номера КИМ. Указывайте то значение, которое хотите видеть в результате. Для соответствия официальному экзамену берите максимальный первичный балл номера КИМ из раздела «Номера КИМ».

## Генерация по правилам

Генерация подбирает задания автоматически. Она удобна для практики и больших банков заданий.

1. Заполните те же поля заголовка: ID учебного года, название, вид, длительность.
2. В поле «Правила генерации» вставьте JSON-массив:

```json
[
  {"kim_number_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abd", "count": 2, "difficulty": "easy", "topic_id": null},
  {"kim_number_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abe", "count": 1, "difficulty": null, "topic_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abf"}
]
```

3. Нажмите «Сгенерировать».

Каждое правило означает: взять `count` заданий указанного номера КИМ, при необходимости — только заданной сложности и только из заданной темы.

Правила отбора:

- `kim_number_id` обязателен; номер должен принадлежать выбранному учебному году;
- `count` должен быть больше нуля;
- `difficulty` необязателен: `easy`, `medium`, `hard` или `null`;
- `topic_id` необязателен: UUID темы или `null`;
- берутся только опубликованные публичные задания (`published` и `is_public`);
- одно задание не может попасть в вариант дважды, даже если подходит под несколько правил;
- задания внутри правила выбираются случайно;
- балл каждого задания равен максимальному первичному баллу его номера КИМ;
- позиции заданий идут подряд: сначала все задания первого правила, затем второго и т. д.

Если подходящих заданий меньше, чем требует правило, вариант не создаётся: вернётся ошибка «недостаточно заданий для генерации варианта». В этом случае уменьшите `count`, уберите фильтр сложности или темы либо опубликуйте больше заданий.

## Список вариантов

В таблице видны название, вид и статус. Для опубликованных вариантов кнопка «Опубликовать» скрыта. Список в интерфейсе показывает до 100 вариантов и не имеет фильтров.

API поддерживает фильтры `exam_year_id` и `status`, а также курсорную пагинацию. Получить полный состав варианта (позиции, задания, баллы) можно через `GET /admin/variants/{id}`; в интерфейсе детальный просмотр не выведен.

## Действия

### Создать вручную

Собирает вариант из перечисленных заданий. Создаётся в статусе `draft`.

### Сгенерировать

Подбирает задания по правилам и создаёт вариант в статусе `draft`. Исходные задания не изменяются.

### Опубликовать

Кнопка «Опубликовать» доступна для всех вариантов, кроме уже опубликованных. Публикация переводит вариант в `published` и делает его доступным ученикам. Отдельной проверки состава при публикации нет: если вариант создан, он публикуется как есть. Поэтому перед публикацией проверьте состав через API или соберите вариант без ошибок.

## Частые ошибки

| Сообщение | Причина | Что сделать |
|---|---|---|
| «учебный год не найден» | Несуществующий ID года. | Проверьте ID в разделе «Учебные годы». |
| «название обязательно» | Пустое название. | Заполните название. |
| «неизвестное назначение варианта» | `kind` не из списка. | Используйте `diagnostic`, `practice` или `mock`. |
| «длительность должна быть положительной» | Минуты меньше или равны нулю. | Укажите положительное число. |
| «вариант должен содержать задания» | Пустой массив `tasks`. | Добавьте хотя бы одно задание. |
| «баллы не могут быть отрицательными» | В `points` отрицательное число. | Укажите 0 или больше. |
| «задание повторяется в варианте» | Один `task_id` указан дважды. | Уберите дубликат. |
| «задание не найдено» | Несуществующий `task_id`. | Проверьте ID задания. |
| «задание принадлежит другому учебному году» | Задание из другого года. | Используйте задание выбранного года или смените год. |
| «правила генерации обязательны» | Пустой массив `rules`. | Добавьте хотя бы одно правило. |
| «количество заданий должно быть положительным» | `count` меньше или равен нулю. | Укажите положительное число. |
| «номер КИМ не найден» | Несуществующий `kim_number_id`. | Проверьте ID номера КИМ. |
| «номер КИМ принадлежит другому учебному году» | Номер из другого года. | Исправьте год или номер. |
| «недостаточно заданий для генерации варианта» | Под фильтр попадает меньше заданий, чем `count`. | Уменьшите `count`, ослабьте фильтры или опубликуйте задания. |

## Чек-лист перед публикацией

- [ ] Учебный год выбран верно.
- [ ] Название понятно ученику.
- [ ] Вид соответствует сценарию: диагностика, практика или пробник.
- [ ] Длительность совпадает с реальным экзаменом или задуманным тренировочным лимитом.
- [ ] Все задания принадлежат выбранному учебному году.
- [ ] Нет повторяющихся заданий.
- [ ] Баллы соответствуют номерам КИМ.
- [ ] Состав варианта проверен.
