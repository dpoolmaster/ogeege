# Задания

Раздел «Задания» — это банк заданий платформы. Каждая запись здесь — одно задание, которое можно использовать в диагностике, тематической практике, пробниках, карте пробелов и персональном плане подготовки.

Задание всегда привязано к конкретному учебному году и номеру КИМ. Дополнительно его можно привязать к теме трека. Пока задание не опубликовано, ученики его не видят: оно существует только в админке.

## Где используется задание

| Место | Что берётся из задания |
|---|---|
| Банк заданий и SEO-страницы | Условие, изображения, сложность, тема опубликованных заданий. |
| Диагностика, практика, пробники | Задания попадают в вариант через раздел «Варианты»; там же задаётся балл за задание. |
| Карта пробелов и план подготовки | Тема задания и номер КИМ определяют, какие темы ученик не освоил. |
| Автопроверка части 1 | `answer_spec` описывает, как сравнивать ответ ученика с эталоном. |
| Проверка части 2 | Для заданий с развёрнутым ответом используются рубрики, AI-черновик и очередь методиста. |
| Статистика и прогноз балла | Номер КИМ и сложность задания участвуют в расчёте первичного и тестового балла. |

## Что подготовить перед созданием

Задание нельзя создать «из воздуха»: сначала должны существовать связанные справочники.

1. **Учебный год** — создаётся в разделе «Учебные годы». Задание привязывается к году, а не к треку напрямую.
2. **Номер КИМ** — создаётся в разделе «Номера КИМ» и должен принадлежать выбранному учебному году.
3. **Тема** (необязательно для черновика) — создаётся в разделе «Темы» и должна относиться к треку выбранного учебного года.
4. **Связь темы с номером КИМ** — для публикации тема должна быть связана с номером КИМ. Связь настраивается на уровне номера КИМ.

Все идентификаторы (`ID учебного года`, `ID номера КИМ`, `ID темы`, `ID задания`) — это UUID. В таблицах разделов они не выводятся. ID задания возвращается API списка заданий и отчётом импорта; ID справочников можно получить из ответов API соответствующих разделов. Если ID неизвестен, уточните его у администратора.

## Статусы и жизненный цикл

| Статус | Что означает | Видят ли ученики |
|---|---|---|
| `draft` | Черновик. Можно свободно редактировать и удалять. | Нет |
| `published` | Опубликовано. Задание доступно для практики и пробников. | Да |
| `archived` | Архив. Задание снято с использования, но история сохранена. | Нет |

Обычный путь: `draft` → `published` → `archived`. Вернуть задание из архива в опубликованное через интерфейс нельзя — создайте новое задание или используйте API.

Удалить можно только черновик (`draft`). Опубликованное и архивное задание удалить нельзя: архивирование сохраняет историю и не ломает уже собранные варианты и результаты учеников.

## Поля задания

| Поле | Обязательно | Что указывать |
|---|---|---|
| **Учебный год** | Да | Выбирается из выпадающего списка учебных годов. |
| **Номер КИМ** | Да | Выбирается из списка номеров выбранного учебного года. Номер должен принадлежать выбранному учебному году. |
| **Тема** | Нет для черновика, да для публикации | Выбирается из списка тем трека выбранного учебного года. Тема должна быть связана с номером КИМ. |
| **Сложность** | Да | `easy` (лёгкое), `medium` (среднее) или `hard` (сложное). |
| **Источник** | Да | Откуда взято задание: `seed`, `fipi`, `sotkaonline` и т. п. |
| **Ссылка на источник** | Нет | URL или иное указание на первоисточник. |
| **Отображаемый ответ** | Нет | Эталон ответа в человекочитаемом виде. Показывается ученику и методисту после проверки. |
| **answer_spec JSON** | Да | Машинное описание ответа для автопроверки. Подробно — ниже. |
| **Условие** | Да | Текст задания в Markdown. Редактируется визуальным редактором. |
| **Статус** | — | При создании всегда `draft`. Меняется кнопками «Опубликовать» и «В архив». |
| **Версия** | — | Начинается с `1`. Увеличивается при редактировании опубликованного задания. |

### Подробно о полях

**Учебный год и номер КИМ.** Это «место» задания в экзамене. По номеру КИМ платформа понимает часть экзамена, тип ответа и максимальный первичный балл. Номер КИМ выбирается из списка номеров выбранного учебного года, поэтому сначала выберите год. Если номер КИМ относится к другому году, сервер отклонит сохранение с ошибкой «номер КИМ принадлежит другому учебному году».

**Тема.** Тема нужна для диагностики и плана. Список тем ограничен треком выбранного учебного года. Без темы задание может существовать как черновик, но опубликовать его нельзя. При публикации проверяется, что тема относится к тому же треку, что и учебный год, и что тема связана с номером КИМ. Если тема не связана с номером КИМ, публикация отклоняется.

**Сложность.** Влияет на подбор заданий при генерации вариантов. Используйте `easy` для базовых заданий, `medium` для типовых экзаменационных, `hard` для заданий повышенной сложности.

**Источник и ссылка.** Нужны для методической проверки и разбора спорных заданий. Поле «Источник» обязательно, «Ссылка на источник» — нет.

**Отображаемый ответ.** Это не то же самое, что `answer_spec`. Здесь пишется ответ так, как его должен увидеть человек: `2,5`, `[-3; 2]`, `1324`, «решение на фото». Автопроверка использует `answer_spec`, а не это поле.

**Условие.** Markdown с поддержкой формул LaTeX. Визуальный редактор сохраняет текст в Markdown. При сохранении сервер проверяет сбалансированность формул: парные `$`, `$$`, фигурные скобки, `\left`/`\right`, `\begin`/`\end`. Незакрытая формула — ошибка сохранения.

**Версия.** Черновик редактируется без изменения версии. Если отредактировать опубликованное задание, предыдущая версия уходит в историю, а номер версии увеличивается на 1. История версий доступна через API задания.

## Формат `answer_spec`

`answer_spec` — это JSON-объект, который описывает, как проверять ответ ученика. Поле `kind` обязательно. Допустимые значения:

| `kind` | Для чего | Пример |
|---|---|---|
| `number` | Числовой ответ, в том числе дробный. | `{"kind":"number","accepted":["2.5","5/2"],"tolerance":{"type":"absolute","value":0.001}}` |
| `interval` | Ответ в виде промежутка. | `{"kind":"interval","accepted":["[-2;3]","(-2;3)"],"normalize_order":false}` |
| `digits` | Последовательность цифр. | `{"kind":"digits","accepted":["1324"],"length":4,"order_matters":false}` |
| `text` | Текстовый ответ. | `{"kind":"text","accepted":["Москва"],"case_sensitive":false}` |
| `choice` | Выбор одного или нескольких вариантов. | `{"kind":"choice","accepted":["2"]}` |
| `extended` | Развёрнутый ответ части 2. | `{"kind":"extended","rubric_id":"<uuid>"}` |

Важно: сейчас сервер проверяет только то, что `answer_spec` — корректный JSON и что `kind` входит в список выше. Остальные поля (`accepted`, `tolerance`, `length` и т. д.) сохраняются как есть и будут использоваться автопроверкой части 1. Поэтому заполняйте их сразу по формату — иначе задание опубликуется, но автопроверка позже не сможет с ним работать.

### `number`

```json
{
  "kind": "number",
  "accepted": ["12"],
  "tolerance": null,
  "units": ["см", "м"],
  "case_sensitive": false
}
```

- `accepted` — список допустимых записей ответа. Лучше перечислять все равносильные формы: `["0.5", "1/2"]`.
- `tolerance` — допустимое отклонение. `{"type":"absolute","value":0.01}` означает ±0,01.
- `units` — допустимые единицы измерения, если ответ должен содержать единицу.

### `interval`

```json
{
  "kind": "interval",
  "accepted": ["[-3;2]", "(-3;2)"],
  "normalize_order": false
}
```

`normalize_order` включает приведение границ к одному порядку. Если ответ должен совпадать строго с записью — оставьте `false`.

### `digits`

```json
{
  "kind": "digits",
  "accepted": ["1324"],
  "length": 4,
  "order_matters": false
}
```

`length` задаёт количество цифр, `order_matters` — важен ли порядок. Для ответов, где порядок не важен, используйте `false`.

### `text`

```json
{
  "kind": "text",
  "accepted": ["Москва"],
  "case_sensitive": false
}
```

`case_sensitive` управляет учётом регистра. Для обычных текстовых ответов оставляйте `false`.

### `choice`

```json
{
  "kind": "choice",
  "accepted": ["2"]
}
```

`accepted` содержит номера или буквы правильных вариантов. Если правильных вариантов несколько, перечислите все: `["1","3"]`.

### `extended`

```json
{
  "kind": "extended",
  "rubric_id": "<uuid рубрики>"
}
```

Используется для заданий части 2. Ответ проверяется по рубрике: AI готовит черновик, методист подтверждает или исправляет. Для `extended` указывайте `rubric_id`; если в вашей версии рубрики задаются кодом, используйте `rubric_code`.

### Как выбрать `kind`

- Номер КИМ с типом ответа `short` — используйте `number`, `interval`, `digits`, `text` или `choice`.
- Номер КИМ с типом ответа `extended` — используйте `extended` и рубрику.
- Если ответ — число, не используйте `text`: автопроверка не сможет корректно сравнить `2,5` и `2.5`.
- Если ответ — промежуток, не используйте `number`: скобки и порядок границ важны.

## Фильтры и список заданий

Форма фильтра содержит:

- **Учебный год** — оставляет задания выбранного года.
- **Номер КИМ** — оставляет задания выбранного номера. Список номеров ограничен выбранным учебным годом; при смене года номер сбрасывается.
- **Статус** — `draft`, `published`, `archived` или «Любой статус».
- **Поиск** — подстрока в тексте условия, без учёта регистра.

Фильтр по теме поддерживается API, но в форме списка не выведен. Список в интерфейсе показывает до 100 записей (первую страницу); API отдаёт до 200 за запрос с курсорной пагинацией.

В таблице видны первые 80 символов условия, статус и версия. ID задания в таблице не выводится.

## Действия

### Создать задание

1. Заполните обязательные поля: учебный год, номер КИМ, сложность, источник, `answer_spec`.
2. Напишите условие в визуальном редакторе.
3. Нажмите «Сохранить». Задание создаётся в статусе `draft`.
4. Проверьте задание, при необходимости отредактируйте.
5. Нажмите «Опубликовать». Публикация возможна только после заполнения темы и связи темы с номером КИМ.

Повторное сохранение того же условия отклоняется: банк не допускает дубликатов по тексту условия (пробелы и переводы строк нормализуются).

### Изменить задание

Нажмите «Изменить» в строке задания. Форма заполнится текущими значениями. После «Сохранить» изменения применяются сразу. Для опубликованного задания предыдущая версия сохраняется в истории, а версия увеличивается.

Кнопка «Отмена» сбрасывает только текст условия, `answer_spec`, отображаемый ответ и режим редактирования. Остальные поля формы остаются как были.

### Опубликовать

Кнопка «Опубликовать» доступна для всех статусов, кроме `published`. При публикации сервер повторно проверяет:

- учебный год и номер КИМ существуют и согласованы;
- сложность допустима;
- условие и источник не пустые;
- `answer_spec` корректен;
- формулы LaTeX сбалансированы;
- тема указана, существует, относится к треку года и связана с номером КИМ.

После публикации задание становится публичным (`is_public = true`) и может попадать в варианты для учеников.

### В архив

Кнопка «В архив» доступна для опубликованных заданий. Задание перестаёт быть публичным, но остаётся в базе и в истории. Уже созданные варианты и результаты не удаляются.

### Удалить

Кнопка «Удалить» удаляет только черновик. Если задание уже опубликовано или отправлено в архив, сервер вернёт конфликт. Если черновик уже включён в вариант, удаление также не пройдёт: сначала уберите задание из варианта.

### Импортировать

Импорт создаёт несколько заданий за один раз. В поле вставляется JSON-массив объектов. Каждый объект имеет те же поля, что и форма создания:

```json
[
  {
    "exam_year_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abc",
    "kim_number_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abd",
    "topic_id": "0193f0c4-7a2b-7c3d-8e4f-123456789abe",
    "difficulty": "easy",
    "statement_md": "Найдите значение выражения $2 + 2$.",
    "answer_spec": {"kind": "number", "accepted": ["4"]},
    "answer_display": "4",
    "source": "seed",
    "source_ref": ""
  }
]
```

`topic_id` можно не указывать или передать `null`. Статус импортированных заданий всегда `draft`: импорт никогда не публикует задания автоматически.

После импорта показывается отчёт:

- **Создано** — задания добавлены, для каждого известен ID.
- **Пропущено** — условие уже есть в банке; в отчёте будет ID существующего задания.
- **Отклонено** — задание не прошло валидацию; в отчёте указана причина.

Если в массиве есть некорректный UUID, отклоняется весь запрос импорта. Ошибки валидации отдельных заданий (пустое условие, плохой `answer_spec`, неизвестная сложность) не отменяют остальные задания: такие элементы попадают в «Отклонено».

### Загрузить изображение

Изображения нужны для заданий с рисунками, графиками и чертежами.

1. Укажите ID задания.
2. Выберите файл.
3. Нажмите «Загрузить».

Ограничения:

- форматы: PNG, JPEG, GIF, WebP;
- размер: не более 5 МиБ;
- файл не должен быть пустым;
- тип определяется по содержимому, а не по расширению.

Файл сохраняется в хранилище и становится доступен по адресу `/media/<storage_key>`. Чтобы показать изображение в условии, вставьте в Markdown ссылку на этот адрес:

```markdown
![Чертёж к задаче](/media/tasks/<task-id>/<file-id>.png)
```

Загрузка изображения сама по себе не меняет текст условия. ID задания не выводится в таблице: используйте ID из отчёта импорта или из ответа API списка заданий.

## Частые ошибки

| Сообщение | Причина | Что сделать |
|---|---|---|
| «учебный год не найден» | Указан несуществующий ID года. | Проверьте ID в разделе «Учебные годы». |
| «номер КИМ не найден» | Указан несуществующий ID номера. | Проверьте ID в разделе «Номера КИМ». |
| «номер КИМ принадлежит другому учебному году» | Номер относится к другому году. | Выберите номер из нужного года или исправьте год. |
| «неизвестная сложность» | Значение не `easy`, `medium` или `hard`. | Выберите сложность из списка. |
| «правила проверки обязательны» | `answer_spec` пустой. | Заполните JSON с полем `kind`. |
| «правила проверки должны быть корректным JSON» | В `answer_spec` синтаксическая ошибка. | Исправьте JSON; в интерфейсе он разбирается до отправки. |
| «неизвестный тип правил проверки» | `kind` не из списка. | Используйте `number`, `interval`, `digits`, `text`, `choice` или `extended`. |
| «тема обязательна для публикации» | У задания нет темы. | Укажите тему перед публикацией. |
| «тема не найдена» | Несуществующий ID темы. | Проверьте ID в разделе «Темы». |
| «тема принадлежит другому треку» | Тема из другого трека, чем учебный год. | Выберите тему того же трека. |
| «тема не связана с номером КИМ» | Нет связи темы и номера КИМ. | Настройте связь темы с номером КИМ. |
| «пустая формула LaTeX» | В условии есть `$ $` без содержимого. | Удалите пустую формулу или заполните её. |
| «несбалансированные скобки в формуле LaTeX» | Не закрыта `{` или `}`. | Проверьте парность скобок. |
| «несбалансированные окружения LaTeX» | Не совпадают `\begin{...}` и `\end{...}`. | Закройте окружение. |
| «несбалансированные \left и \right» | Есть `\left` без `\right` или наоборот. | Сделайте пары. |
| «условие уже существует в банке» | Дубликат по тексту условия. | Найдите существующее задание или измените условие. |
| «нельзя удалить задание в статусе …» | Задание не черновик. | Используйте архивирование. |
| «недопустимый тип файла» | Файл не PNG/JPEG/GIF/WebP. | Конвертируйте изображение. |
| «размер файла превышает … байт» | Файл больше 5 МиБ. | Сожмите изображение. |
| «батч импорта пуст» | Передан пустой массив. | Добавьте хотя бы одно задание. |

## Чек-лист перед публикацией

- [ ] Учебный год и номер КИМ согласованы.
- [ ] Указана тема того же трека.
- [ ] Тема связана с номером КИМ.
- [ ] Условие заполнено, формулы LaTeX закрыты.
- [ ] Указан источник.
- [ ] `answer_spec` соответствует типу ответа и содержит `accepted`.
- [ ] Отображаемый ответ совпадает с эталоном.
- [ ] Изображения, если нужны, загружены и вставлены в условие.
- [ ] Задание проверено в режиме редактирования до нажатия «Опубликовать».
