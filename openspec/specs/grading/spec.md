# grading Specification

## Purpose

Определяет единые правила автоматической проверки коротких ответов по типу, заданному в данных задания: нормализацию, сравнение, допуск, единицы измерения, выбор из вариантов и объяснимый результат проверки.

## Requirements

### Requirement: Реестр стратегий проверки

Система SHALL выбирать стратегию проверки по значению `answer_spec.kind`. Набор поддерживаемых типов MUST быть единым для учебного цикла и административного контура. Неизвестный или пустой `kind` MUST отклоняться с понятной ошибкой. Добавление нового типа ответа MUST NOT требовать изменения сценариев учебного цикла.

#### Scenario: Известный тип ответа

- **WHEN** задание содержит `answer_spec.kind`, для которого зарегистрирована стратегия
- **THEN** проверка выполняется по правилам этого типа

#### Scenario: Неизвестный тип ответа

- **WHEN** задание содержит `answer_spec.kind`, для которого нет стратегии
- **THEN** проверка отклоняется с понятной ошибкой, а ответ не считается верным

#### Scenario: Новый тип без правки учебного цикла

- **WHEN** в реестр добавляется новый тип ответа
- **THEN** учебный цикл продолжает вызывать единую проверку без ветвлений по типу

### Requirement: Нормализация и сравнение чисел

Система SHALL нормализовать числовой ответ перед сравнением: десятичная запятая и точка MUST быть равнозначны, пробелы и разделители тысяч MUST удаляться, все виды минуса MUST приводиться к `-`, обыкновенная дробь MUST сравниваться по значению с десятичной записью. Сравнение MUST поддерживать список допустимых ответов, абсолютный и относительный допуск и удаление допустимых единиц измерения.

#### Scenario: Десятичная запятая

- **WHEN** ученик вводит `2,5`, а эталон содержит `2.5`
- **THEN** ответ считается верным

#### Scenario: Обыкновенная дробь

- **WHEN** ученик вводит `5/2`, а эталон содержит `2.5`
- **THEN** ответ считается верным

#### Scenario: Варианты минуса и разделители тысяч

- **WHEN** ученик вводит `− 1 000`, а эталон содержит `-1000`
- **THEN** ответ считается верным

#### Scenario: Абсолютный допуск

- **WHEN** задание задаёт абсолютный допуск и разница ответа с эталоном не превышает допуск
- **THEN** ответ считается верным

#### Scenario: Относительный допуск

- **WHEN** задание задаёт относительный допуск и разница ответа с эталоном не превышает долю от эталона
- **THEN** ответ считается верным

#### Scenario: Единицы измерения

- **WHEN** ученик вводит число с допустимой единицей измерения, а эталон содержит число без единицы
- **THEN** единица удаляется перед сравнением и ответ считается верным

#### Scenario: Несколько допустимых ответов

- **WHEN** задание содержит несколько эквивалентных эталонных ответов и ответ ученика совпадает с любым из них
- **THEN** ответ считается верным

### Requirement: Интервалы и множества

Система SHALL нормализовать интервалы и множества: скобки, разделители, пробелы и порядок элементов. Круглая и квадратная скобки MUST различаться, если задание требует учёта включения границ. Порядок элементов MUST игнорироваться, если задание не требует обратного. Ответ, не являющийся корректным интервалом или множеством, MUST считаться неверным без ошибки выполнения.

#### Scenario: Эквивалентная запись интервала

- **WHEN** ученик вводит `[-2; 3]`, а эталон содержит `[-2;3]`
- **THEN** ответ считается верным

#### Scenario: Разные границы интервала

- **WHEN** ученик вводит `(-2;3)`, а эталон содержит `[-2;3]` и задание требует учёта границ
- **THEN** ответ считается неверным

#### Scenario: Множество без учёта порядка

- **WHEN** ученик вводит элементы множества в другом порядке, а задание не требует учёта порядка
- **THEN** ответ считается верным

#### Scenario: Некорректная запись

- **WHEN** ученик вводит строку, которая не является корректным интервалом или множеством
- **THEN** ответ считается неверным, а проверка завершается без ошибки выполнения

### Requirement: Последовательности цифр

Система SHALL сравнивать последовательности цифр с учётом заданной длины и порядка. Если задание требует фиксированной длины, ответ другой длины MUST считаться неверным. Если порядок не важен, одинаковый набор цифр MUST считаться верным независимо от порядка.

#### Scenario: Совпадение последовательности

- **WHEN** ученик вводит последовательность, совпадающую с эталоном по цифрам и порядку
- **THEN** ответ считается верным

#### Scenario: Неверная длина

- **WHEN** ученик вводит последовательность длины, отличной от заданной
- **THEN** ответ считается неверным

#### Scenario: Порядок не важен

- **WHEN** ученик вводит те же цифры в другом порядке, а задание не требует учёта порядка
- **THEN** ответ считается верным

### Requirement: Текстовый ответ

Система SHALL нормализовать текстовый ответ по настройкам задания: учитывать или игнорировать регистр, различать или объединять `ё` и `е`, учитывать или игнорировать дефисы и повторные пробелы. Задание MUST поддерживать несколько допустимых формулировок.

#### Scenario: Регистр не важен

- **WHEN** ученик вводит ответ в другом регистре, а задание не требует учёта регистра
- **THEN** ответ считается верным

#### Scenario: Замена ё на е

- **WHEN** ученик вводит `е` вместо `ё`, а задание разрешает такую замену
- **THEN** ответ считается верным

#### Scenario: Несколько формулировок

- **WHEN** ответ ученика совпадает с одной из допустимых формулировок задания
- **THEN** ответ считается верным

### Requirement: Выбор из вариантов

Система SHALL проверять ответ типа `choice` по вариантам ответа задания, а не по захардкоженному списку. Правильный набор вариантов MUST задаваться в данных задания. Если задание допускает несколько правильных вариантов, ответ MUST сравниваться как набор без учёта порядка. Ответ с несуществующим вариантом MUST считаться неверным.

#### Scenario: Верный вариант

- **WHEN** ученик выбирает вариант, который задание отметило правильным
- **THEN** ответ считается верным

#### Scenario: Неверный вариант

- **WHEN** ученик выбирает вариант, который задание не отметило правильным
- **THEN** ответ считается неверным

#### Scenario: Несколько правильных вариантов

- **WHEN** задание требует несколько правильных вариантов и ученик выбрал их все в любом порядке
- **THEN** ответ считается верным

#### Scenario: Несуществующий вариант

- **WHEN** ученик отправляет идентификатор варианта, которого нет у задания
- **THEN** ответ считается неверным, а проверка не раскрывает правильный набор

### Requirement: Объяснимый результат проверки

Система SHALL возвращать результат проверки с причиной: совпало, не совпало, частично или требует проверки. Результат MUST содержать нормализованный ответ ученика и эталонные ответы, если они допустимы к раскрытию после отправки. Для неподдерживаемого типа причина MUST явно указывать, что автоматическая проверка недоступна.

#### Scenario: Причина «совпало»

- **WHEN** ответ признан верным
- **THEN** результат содержит причину «совпало» и нормализованный ответ

#### Scenario: Причина «не совпало»

- **WHEN** ответ признан неверным
- **THEN** результат содержит причину «не совпало» и нормализованный ответ

#### Scenario: Неподдерживаемый тип

- **WHEN** проверка вызывается для типа, недоступного автоматической проверке
- **THEN** результат содержит причину, указывающую на необходимость другой проверки

### Requirement: Валидация правил проверки

Система SHALL валидировать `answer_spec` по схеме его типа до сохранения задания. Обязательные поля типа MUST проверяться. Неизвестный `kind`, некорректный JSON и недопустимые значения MUST отклоняться с понятной ошибкой. Для `choice` каждый правильный идентификатор MUST существовать среди вариантов задания.

#### Scenario: Корректные правила

- **WHEN** сохраняется задание с корректным `answer_spec` известного типа
- **THEN** правила принимаются

#### Scenario: Неизвестный тип

- **WHEN** сохраняется задание с неизвестным `answer_spec.kind`
- **THEN** сохранение отклоняется с понятной ошибкой

#### Scenario: Некорректное поле типа

- **WHEN** сохраняется задание с недопустимым значением обязательного поля типа
- **THEN** сохранение отклоняется с ошибкой валидации

#### Scenario: Вариант отсутствует у задания

- **WHEN** `choice` ссылается на вариант, которого нет среди вариантов задания
- **THEN** сохранение отклоняется, а задание не меняется
