# help Specification

## Purpose

Обеспечивает встроенную справку по разделам интерфейса: для каждого раздела существует документ, описывающий его назначение и правила работы, доступный прямо со страницы раздела по кнопке «?». Справка хранится вместе с кодом и поддерживается в актуальном состоянии.

## Requirements

### Requirement: Справочный документ на каждый раздел

Система SHALL иметь отдельный справочный документ для каждого раздела административного интерфейса: треки, учебные годы, номера КИМ, темы, теория, задания, варианты, рубрики, шкалы, пользователи, аудит. Документ MUST описывать назначение раздела, назначение основных полей и действий и ограничения. Тексты справки MUST быть на русском языке.

#### Scenario: Справка по разделу заданий

- **WHEN** открыта справка раздела «Задания»
- **THEN** документ описывает назначение раздела, работу с фильтром, создание и изменение задания, импорт, публикацию, архивирование и загрузку изображений

#### Scenario: Справка по разделу шкал

- **WHEN** открыта справка раздела «Шкалы»
- **THEN** документ описывает назначение шкалы перевода и правила заполнения диапазонов

#### Scenario: Отсутствующий документ

- **WHEN** для зарегистрированного раздела отсутствует документ или документ пуст
- **THEN** проверка полноты справки завершается ошибкой и не пропускает сборку

### Requirement: Доступ к справке по роли

Система SHALL выдавать справку только аутентифицированному пользователю с ролью методиста или администратора. Справка по разделам «Пользователи» и «Аудит» MUST быть доступна только администратору. Запрос справки по неизвестному разделу MUST возвращать ошибку «не найдено».

#### Scenario: Методист открывает справку раздела контента

- **WHEN** методист запрашивает справку раздела «Задания»
- **THEN** документ возвращается

#### Scenario: Методист запрашивает справку пользователей

- **WHEN** методист запрашивает справку раздела «Пользователи»
- **THEN** запрос отклоняется как запрещённый, а содержимое документа не раскрывается

#### Scenario: Неаутентифицированный запрос

- **WHEN** неаутентифицированный пользователь запрашивает справку любого раздела
- **THEN** запрос отклоняется с требованием входа

#### Scenario: Неизвестный раздел

- **WHEN** запрашивается справка по незарегистрированному идентификатору раздела
- **THEN** возвращается ответ «не найдено»

### Requirement: Кнопка справки на странице раздела

Система SHALL показывать на каждой странице раздела административного интерфейса кнопку «?», открывающую всплывающее окно с документом-справкой этого раздела. Кнопка MUST присутствовать на всех одиннадцати экранах без отдельной правки каждого экрана. Всплывающее окно MUST закрываться по явному действию пользователя. Ошибка загрузки справки MUST отображаться внутри окна и MUST NOT блокировать работу раздела.

#### Scenario: Открытие справки

- **WHEN** методист нажимает кнопку «?» на странице раздела
- **THEN** открывается всплывающее окно с документом-справкой текущего раздела

#### Scenario: Переход между разделами

- **WHEN** методист переходит на другой раздел и нажимает кнопку «?»
- **THEN** открывается справка нового раздела, а не предыдущего

#### Scenario: Ошибка загрузки справки

- **WHEN** документ не удалось загрузить
- **THEN** во всплывающем окне показывается сообщение об ошибке, а страница раздела остаётся работоспособной

### Requirement: Актуальность справки

Проект SHALL поддерживать справку в актуальном состоянии. Изменение поведения или полей раздела MUST сопровождаться обновлением соответствующего справочного документа. Проверка полноты MUST подтверждать, что каждый зарегистрированный раздел имеет непустой документ.

#### Scenario: Изменение раздела вместе со справкой

- **WHEN** разработчик меняет поведение или поля раздела
- **THEN** в том же изменении обновляется справочный документ этого раздела

#### Scenario: Новый раздел без справки

- **WHEN** добавляется новый раздел интерфейса без справочного документа
- **THEN** проверка полноты справки обнаруживает пропуск и завершается ошибкой
