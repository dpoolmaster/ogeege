# public-site Specification

## Purpose

Определяет публичный контур платформы: SEO-лендинги треков, открытый банк заданий с проверкой короткого ответа, демо-диагностику, статьи и разборы, лид-форму, sitemap/robots и кэширование публичных страниц.

## Requirements

### Requirement: Публичные лендинги треков

Система SHALL строить публичный лендинг для каждого опубликованного трека по его коду и MUST NOT требовать отдельного маршрута для конкретного предмета. Лендинг MUST содержать описание трека, структуру экзамена, ссылку на демо-диагностику и призыв к регистрации. Прежние адреса лендингов MUST перенаправляться на канонический адрес соответствующего трека. Неопубликованный или неизвестный трек MUST возвращать ошибку «не найдено».

#### Scenario: Публикация нового трека

- **WHEN** публикуется трек с новым кодом
- **THEN** его лендинг становится доступен по адресу, построенному от кода, без изменения кода приложения

#### Scenario: Прежний адрес лендинга

- **WHEN** посетитель открывает прежний адрес лендинга
- **THEN** он перенаправляется на канонический адрес соответствующего трека

#### Scenario: Неопубликованный или неизвестный трек

- **WHEN** посетитель открывает лендинг неопубликованного или неизвестного трека
- **THEN** возвращается ошибка «не найдено»

#### Scenario: Структура экзамена на лендинге

- **WHEN** у опубликованного трека есть опубликованный учебный год
- **THEN** лендинг показывает структуру экзамена и призыв к регистрации

### Requirement: Открытый банк заданий

Система SHALL предоставлять открытый банк заданий без регистрации. В банке MUST отображаться только задания, которые опубликованы, помечены публичными и поддерживают автоматическую проверку. Банк MUST поддерживать фильтрацию по номеру КИМ и теме и MUST выдавать результаты постранично. Черновики, архивные задания и задания без автоматической проверки MUST NOT отображаться.

#### Scenario: Анонимный доступ к банку

- **WHEN** посетитель без входа открывает банк заданий
- **THEN** он видит список доступных заданий

#### Scenario: Фильтрация банка

- **WHEN** посетитель выбирает номер КИМ и тему
- **THEN** список содержит только задания, подходящие под выбранные фильтры

#### Scenario: Постраничная выдача

- **WHEN** подходящих заданий больше, чем помещается на страницу
- **THEN** следующая страница продолжает список без дублей и пропусков

#### Scenario: Скрытие недоступных заданий

- **WHEN** в банке есть черновик, архивное задание или задание без автоматической проверки
- **THEN** такое задание не отображается посетителю

### Requirement: Проверка ответа в открытом банке

Система SHALL позволять посетителю без регистрации ввести ответ на задание банка и MUST показать результат проверки и краткое объяснение. Ответ MUST NOT сохраняться в историю без регистрации. Правила проверки и эталонный ответ MUST NOT раскрываться до отправки ответа. Задание с типом ответа, который не поддерживается публичной проверкой, MUST NOT предлагаться для проверки.

#### Scenario: Верный ответ

- **WHEN** посетитель вводит верный ответ
- **THEN** показывается результат «верно» и краткое объяснение

#### Scenario: Неверный ответ

- **WHEN** посетитель вводит неверный ответ
- **THEN** показывается результат «неверно» и корректный ответ с кратким объяснением

#### Scenario: Ответ не сохраняется

- **WHEN** проверка ответа завершена
- **THEN** ответ не сохраняется в историю и не связывается с учётной записью

#### Scenario: Скрытие правил проверки

- **WHEN** посетитель открывает карточку задания до отправки ответа
- **THEN** правила проверки и эталонный ответ не раскрываются

#### Scenario: Неподдерживаемый тип ответа

- **WHEN** задание требует проверки, недоступной в публичном контуре
- **THEN** оно не предлагается для проверки в банке

### Requirement: Демо-диагностика

Система SHALL предоставлять демо-диагностику из 5–7 публичных заданий. Результат MUST показываться без регистрации и MUST содержать итог и разбивку по темам. Полный отчёт MUST быть доступен после регистрации. Результат демо MUST NOT сохраняться как учебная сессия. Данные демо MUST быть ограничены по времени и MUST отклоняться при истечении или изменении.

#### Scenario: Запуск демо-диагностики

- **WHEN** посетитель запускает демо-диагностику по опубликованному треку
- **THEN** он получает от 5 до 7 публичных заданий

#### Scenario: Результат без регистрации

- **WHEN** посетитель отправляет ответы демо-диагностики
- **THEN** показывается итог и разбивка по темам без входа в систему

#### Scenario: Призыв к полному отчёту

- **WHEN** показан результат демо-диагностики
- **THEN** посетителю предлагается регистрация для получения полного отчёта

#### Scenario: Результат не сохраняется

- **WHEN** демо-диагностика завершена
- **THEN** результат не создаёт учебную сессию и не сохраняется в историю

#### Scenario: Истёкшие или изменённые данные демо

- **WHEN** данные демо-диагностики истекли или были изменены
- **THEN** проверка отклоняется с понятной ошибкой

### Requirement: Статьи и разборы

Система SHALL предоставлять список и страницы опубликованных статей и разборов. Содержимое MUST отображаться из Markdown с санитизацией HTML. Страница MUST содержать SEO-метаданные, канонический адрес и хлебные крошки. Неопубликованные статьи MUST NOT быть доступны публично.

#### Scenario: Список статей

- **WHEN** посетитель открывает список статей
- **THEN** он видит только опубликованные статьи

#### Scenario: Страница статьи

- **WHEN** посетитель открывает опубликованную статью
- **THEN** отображаются содержимое, SEO-метаданные и хлебные крошки

#### Scenario: Черновик статьи

- **WHEN** статья не опубликована
- **THEN** её страница недоступна публично

#### Scenario: Санитизация статьи

- **WHEN** статья содержит небезопасный HTML
- **THEN** он удаляется при отображении

### Requirement: Лид-форма

Система SHALL принимать заявки с публичной формы: имя, контакт и комментарий. Заявка MUST валидироваться, MUST сохраняться и MUST порождать уведомление администратору. Форма MUST применять антиспам-защиту и ограничение частоты. Ошибка уведомления MUST NOT терять сохранённую заявку. Персональные данные MUST NOT попадать в логи.

#### Scenario: Успешная заявка

- **WHEN** посетитель отправляет корректные данные лид-формы
- **THEN** заявка сохраняется, а администратор получает уведомление

#### Scenario: Ошибка валидации заявки

- **WHEN** обязательные поля пусты или превышают допустимый размер
- **THEN** заявка не сохраняется, а посетитель видит ошибку

#### Scenario: Антиспам

- **WHEN** срабатывает скрытое поле-ловушка или превышен лимит частоты
- **THEN** заявка не создаётся, а посетитель получает нейтральный ответ

#### Scenario: Ошибка уведомления

- **WHEN** уведомление администратору не удалось поставить в очередь
- **THEN** заявка остаётся сохранённой, а ошибка логируется без персональных данных

#### Scenario: Персональные данные в логах

- **WHEN** заявка обрабатывается
- **THEN** контакт и комментарий не записываются в логи

### Requirement: Sitemap и robots

Система SHALL генерировать `/sitemap.xml` и `/robots.txt`. Sitemap MUST содержать канонические публичные адреса опубликованных треков, статей и страниц и MUST NOT содержать черновики, служебные и личные страницы. Robots MUST запрещать обход личных и административных разделов и MUST ссылаться на sitemap.

#### Scenario: Публикация в sitemap

- **WHEN** контент опубликован
- **THEN** его канонический адрес появляется в sitemap

#### Scenario: Исключения из sitemap

- **WHEN** есть черновики, служебные или личные страницы
- **THEN** они отсутствуют в sitemap

#### Scenario: Правила robots

- **WHEN** запрашивается `robots.txt`
- **THEN** он запрещает обход личных и административных разделов и содержит ссылку на sitemap

#### Scenario: Типы содержимого sitemap и robots

- **WHEN** запрашиваются `sitemap.xml` и `robots.txt`
- **THEN** возвращаются корректные типы содержимого

### Requirement: Кэширование публичных страниц

Система SHALL кэшировать успешные ответы публичных GET-страниц на 60 секунд по ключу URL для анонимных посетителей. Аутентифицированные запросы MUST NOT получать общий кэш. Формы на закэшированной странице MUST оставаться работоспособными: CSRF-токен MUST подставляться при выдаче. Ошибочные ответы MUST NOT кэшироваться.

#### Scenario: Повторный запрос

- **WHEN** анонимный посетитель повторно запрашивает ту же страницу в пределах 60 секунд
- **THEN** ответ берётся из кэша

#### Scenario: Истечение кэша

- **WHEN** 60 секунд истекли
- **THEN** страница формируется заново

#### Scenario: Аутентифицированный запрос

- **WHEN** запрос содержит действующую сессию
- **THEN** общий кэш не используется

#### Scenario: CSRF на закэшированной странице

- **WHEN** закэшированная страница содержит форму
- **THEN** выданный CSRF-токен действителен для отправки формы

#### Scenario: Ошибка не кэшируется

- **WHEN** публичная страница возвращает ошибку
- **THEN** такой ответ не кэшируется

### Requirement: Безопасность и видимость публичного контура

Система SHALL показывать публично только опубликованный контент. Все пользовательские данные MUST валидироваться и экранироваться. Markdown MUST санитизироваться по allowlist. Изменяющие публичные запросы MUST требовать CSRF-токен. Публичные формы MUST иметь ограничение частоты. Ответы учеников и контактные данные MUST NOT попадать в логи. Личные страницы MUST быть закрыты от индексации.

#### Scenario: Только опубликованный контент

- **WHEN** публичная страница запрашивает трек, задание или статью
- **THEN** неопубликованные данные не показываются

#### Scenario: Опасный HTML

- **WHEN** в условии задания или статье есть опасный HTML
- **THEN** он удаляется при отображении

#### Scenario: Отсутствие CSRF-токена

- **WHEN** изменяющий публичный запрос отправлен без CSRF-токена
- **THEN** запрос отклоняется

#### Scenario: Превышение частоты

- **WHEN** превышен лимит запросов публичной формы
- **THEN** запрос отклоняется

#### Scenario: Логи без персональных данных

- **WHEN** обрабатывается ответ ученика или заявка
- **THEN** персональные данные и ответы не записываются в логи

#### Scenario: Закрытие личных страниц от индексации

- **WHEN** поисковый робот запрашивает личную страницу
- **THEN** индексация такой страницы запрещена
