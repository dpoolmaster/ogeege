## Why

В админке одиннадцать экранов, у каждого своя логика (импорт заданий, версии теории, шкалы перевода, права ролей), но нигде нет встроенной справки. Методист вынужден держать это в голове или спрашивать разработчика. Справка нужна прямо на странице раздела и должна обновляться вместе с кодом, иначе она быстро устареет и начнёт вводить в заблуждение.

## What Changes

- Появляется набор документов-справок: по одному Markdown-файлу на каждый раздел админки (11 файлов).
- Появляется модуль `internal/help`: реестр разделов, загрузка документов из встроенных файлов и отдача их как безопасного HTML.
- Появляется API `GET /api/help/:id`, возвращающий `{title, html}` с проверкой доступа по роли.
- На странице каждого раздела появляется кнопка «?», открывающая всплывающее окно (`<dialog>`) с документом-справкой.
- Актуальность поддерживается механически: unit-тест проверяет, что у каждого зарегистрированного раздела есть непустой документ, а в `AGENTS.md` и ТЗ добавляются правила обновлять справку вместе с изменением раздела.

Поведение существующих экранов, API, маршрутов и данных не меняется — изменение аддитивное.

## Capabilities

### New Capabilities

- `help`: справочные документы по разделам интерфейса, доступ к ним по роли, кнопка «?» с всплывающим окном и правила поддержания справки в актуальном состоянии.

### Modified Capabilities

Нет. Справка аддитивна и не меняет требований существующих capability.

## Impact

- Новый модуль `internal/help/` (`registry.go`, `service.go`, `handler.go`, `docs/*.md`, тесты).
- `cmd/server/main.go` — регистрация маршрута `/api/help/:id`.
- `web/admin/src/App.vue` — монтирование кнопки «?» над `<router-view/>`.
- `web/admin/src/components/HelpButton.vue` — новый компонент с диалогом.
- `web/admin/src/style.css` — стили кнопки и диалога.
- `web/admin/dist/*` — пересборка через `npm run build` (встроена в бинарь через `go:embed`).
- `docs/technical-specification.md` — новый подраздел о справке, пункт в Definition of Done, строка соответствия AGENTS.md.
- `AGENTS.md` — правило обновлять справку раздела и пункт в Definition of Done / финальной проверке.
- Новых зависимостей Go и npm не добавляется: Markdown рендерится существующим `internal/shared/markdown`.
