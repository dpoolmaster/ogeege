## Context

См. `proposal.md` (Why/What). В репозитории нет существующих спеков под эту тему; нужен один поддерживаемый Markdown-файл со списком русскоязычных источников ОГЭ/ЕГЭ (Telegram/VK/MAX + сайты), включая официальные источники и СМИ.

## Goals / Non-Goals

**Goals:**
- Зафиксировать расположение и формат итогового артефакта списка в репо.
- Описать единую структуру разделов и шаблон полей записей в соответствии со specs (`oge-ege-sources-list`).
- Задать минимальные соглашения: язык/контекст RU-only, тип источника (официальный / СМИ / иное сообщество/категория, явно указываемая в тексте), темы `подготовка`, `сдача`, `проведение`, формат даты проверки/актуализации `YYYY-MM-DD`.

**Non-Goals:**
- Автоматический сбор/парсинг, боты, API-интеграции (отдельная работа позже).
- Валидация ссылок скриптами на этом этапе.
- Дизайн веб-сайта или UI вокруг списка.

## Decisions

- **Расположение итогового файла:** `docs/oge-ege-sources-ru.md` (создаётся при реализации задач). Альтернатива `data/oge-ege-sources-ru.md` — отвергнута в пользу `docs/` как «документационного» списка для людей; при желании путь можно сменить в tasks без изменения сути specs.
- **Структура документа:** H1 заголовок; H2 разделы: `## Telegram`, `## VK`, `## MAX`, `## Сайты`. Внутри каждого раздела записи в виде маркированного списка (`- ...`) для простоты правок в PR/review.
- **Формат записи (единый шаблон, адаптация по платформе):**
  - Telegram: `- Название — ссылка или @handle (тип: канал|группа) | тип источника: ... | темы: подготовка/сдача/проведение (через запятую) | кратко: ... | проверено: YYYY-MM-DD`
  - VK: аналогично, `тип: сообщество/группа/канал (как в VK)` по факту.
  - MAX: аналогично по смыслу (тип сущности указывать, как применимо).
  - Сайты: без поля «тип сущности платформы», иначе те же смысловые поля: название, URL, тип источника, темы, кратко, проверено.
- **Тип источника:** явно текстом одно из: `официальный источник`, `СМИ`, `сообщество` (или иная короткая категория, но согласованная в файле); в первом приближении использовать эти три варианта.
- **Темы:** перечисление подмножеств {подготовка, сдача, проведение}. Если тема не относится — не указывать.
- **Дата:** `проверено: YYYY-MM-DD` (дата последней ручной проверки актуальности ссылки/описания).

## Risks / Trade-offs

- Ручное ведение → риск устаревания ссылок → Mitigation: обязательное поле `проверено` и периодический пересмотр (процесс вне этого change).
- Свободный текст в «кратко» → неоднородность → Mitigation: короткие фразы, при желании позже ввести шаблон; сейчас достаточно согласованного списка полей.
- Путь `docs/` может не совпасть с будущей структурой → Mitigation: зафиксировать в tasks; смена пути — локальная правка.
