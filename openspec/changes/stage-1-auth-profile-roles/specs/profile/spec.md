## Purpose

Определяет персональные данные ученика, согласия и их фиксацию, проверку возраста с согласием законного представителя, учебные цели, настройки уведомлений и удаление аккаунта с обезличиванием, а также доступ пользователя только к собственному профилю.

## ADDED Requirements

### Requirement: Профиль ученика

Система SHALL позволять ученику просматривать и изменять свои персональные данные: имя, фамилию, дату рождения, класс и часовой пояс. Дата рождения MUST быть обязательной для ученика. Система MUST собирать только данные, необходимые для обучения. Все входные данные MUST проверяться на сервере до сохранения.

#### Scenario: Заполнение профиля

- **WHEN** ученик сохраняет имя, фамилию, дату рождения, класс и часовой пояс
- **THEN** данные сохраняются и доступны при последующем просмотре профиля

#### Scenario: Отсутствие обязательных данных

- **WHEN** ученик пытается сохранить профиль без даты рождения
- **THEN** сохранение отклоняется с ошибкой валидации, указывающей обязательное поле

#### Scenario: Некорректные данные

- **WHEN** ученик сохраняет данные в недопустимом формате (например, некорректная дата или несуществующий часовой пояс)
- **THEN** сохранение отклоняется с ошибкой валидации, а прежние данные остаются без изменений

### Requirement: Согласия с фиксацией версии документа

Система SHALL фиксировать отдельные согласия: на обработку персональных данных и, для несовершеннолетних, согласие законного представителя. Каждое согласие MUST храниться вместе с версией документа, временем предоставления и IP-адресом. Отзыв или отсутствие обязательного согласия MUST учитываться при предоставлении доступа к соответствующим возможностям.

#### Scenario: Предоставление согласия

- **WHEN** пользователь предоставляет согласие на обработку персональных данных
- **THEN** сохраняется запись с версией документа, временем и IP-адресом

#### Scenario: Отсутствие обязательного согласия

- **WHEN** пользователь пытается воспользоваться возможностью, требующей обязательного согласия, не предоставив его
- **THEN** действие блокируется с сообщением о необходимости согласия

#### Scenario: Смена версии документа

- **WHEN** версия документа согласия обновляется
- **THEN** ранее зафиксированные согласия сохраняют прежнюю версию и время, а для новой версии требуется новое согласие

### Requirement: Проверка возраста и согласие законного представителя

Система SHALL определять несовершеннолетних по дате рождения. Для несовершеннолетнего MUST требоваться согласие законного представителя; без него несовершеннолетний MUST NOT допускаться к платному обучению. Возраст MUST рассчитываться на сервере.

#### Scenario: Совершеннолетний пользователь

- **WHEN** дата рождения пользователя соответствует возрасту 18 лет и старше
- **THEN** согласие законного представителя не требуется

#### Scenario: Несовершеннолетний без согласия представителя

- **WHEN** несовершеннолетний пользователь пытается начать платное обучение без согласия законного представителя
- **THEN** доступ к платному обучению блокируется с указанием необходимости согласия представителя

#### Scenario: Несовершеннолетний с согласием представителя

- **WHEN** несовершеннолетний пользователь имеет зафиксированное согласие законного представителя
- **THEN** ограничение на платное обучение по возрасту снимается

### Requirement: Учебные цели

Система SHALL позволять ученику задавать учебные цели: трек, дату экзамена, целевой балл и доступное время в неделю. Значения MUST проверяться на сервере. Изменение целей SHALL сохранять историю предыдущих значений, не удаляя её.

#### Scenario: Сохранение учебных целей

- **WHEN** ученик сохраняет трек, дату экзамена, целевой балл и недельное время
- **THEN** цели сохраняются и доступны при последующем чтении

#### Scenario: Некорректная цель

- **WHEN** ученик указывает дату экзамена в прошлом или целевой балл вне допустимого диапазона
- **THEN** сохранение отклоняется с ошибкой валидации

#### Scenario: Изменение целей

- **WHEN** ученик изменяет ранее сохранённые цели
- **THEN** новые значения становятся текущими, а история предыдущих значений сохраняется

### Requirement: Настройки уведомлений

Система SHALL позволять пользователю включать и отключать email-уведомления и недельный отчёт. Настройки MUST применяться при отправке соответствующих писем. Изменение настроек MUST NOT влиять на обязательные сервисные письма, необходимые для безопасности учётной записи.

#### Scenario: Отключение уведомлений

- **WHEN** пользователь отключает email-уведомления
- **THEN** необязательные письма этому пользователю не отправляются, а настройка сохраняется

#### Scenario: Обязательные письма при отключённых уведомлениях

- **WHEN** пользователь отключил email-уведомления, но запрашивает подтверждение email или сброс пароля
- **THEN** обязательное сервисное письмо всё равно отправляется

### Requirement: Удаление аккаунта с обезличиванием

Система SHALL позволять пользователю запросить удаление аккаунта. При обработке запроса персональные данные MUST обезличиваться; данные, которые должны сохраняться по закону, MUST сохраняться в обезличенном виде. После обезличивания учётная запись MUST NOT позволять вход, а прежние сессии MUST быть отозваны.

#### Scenario: Запрос удаления аккаунта

- **WHEN** пользователь запрашивает удаление аккаунта
- **THEN** персональные данные обезличиваются, сессии отзываются, а вход по прежним учётным данным становится невозможен

#### Scenario: Сохранение обязательных записей

- **WHEN** аккаунт обезличивается при наличии записей, подлежащих сохранению по закону
- **THEN** такие записи сохраняются без прямых персональных идентификаторов

### Requirement: Доступ только к собственному профилю

Пользователь MUST иметь доступ только к своему профилю, согласиям, целям и настройкам. Запрос данных другого пользователя MUST отклоняться без раскрытия содержимого. Служебный доступ к профилям, если он требуется для проверки, MUST ограничиваться ролью и не раскрывать лишние персональные данные.

#### Scenario: Доступ к своему профилю

- **WHEN** аутентифицированный пользователь запрашивает свой профиль
- **THEN** возвращаются только его собственные данные

#### Scenario: Доступ к чужому профилю

- **WHEN** пользователь пытается получить или изменить профиль другого пользователя
- **THEN** запрос отклоняется как запрещённый, а данные не раскрываются
