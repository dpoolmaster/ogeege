## Context

См. `proposal.md` — Why. Справочные документы — это Markdown; в проекте уже есть `internal/shared/markdown.Render`, который через goldmark + bluemonday отдаёт безопасный HTML. Админка — Vue SPA (`web/admin`) с маршрутами в `web/admin/src/router.js`; `App.vue` уже держит общий каркас и знает текущего пользователя и роль. Административные API живут в группе `/api/admin` с проверкой роли методиста/администратора; admin-only маршруты (`users`, `audit`) вынесены в отдельную группу.

Ключевое ограничение: `//go:embed` не поднимается в родительские каталоги, поэтому документы должны лежать внутри пакета `internal/help`.

## Goals / Non-Goals

**Goals:**

- Один документ-справка на каждый из 11 экранов админки, версионируемый вместе с кодом.
- Единый способ получить справку для SPA и (в будущем) для серверных страниц.
- Кнопка «?» на всех экранах без правки `views/*.vue`.
- Механическая защита от устаревания: тест полноты реестра.

**Non-Goals:**

- Не менять API, маршруты, права и данные существующих разделов.
- Не вводить БД, админ-редактор справки или CMS: документы — файлы в репозитории.
- Не покрывать публичный контур и страницы auth/account (кода разделов ещё нет).
- Не добавлять новые зависимости Go или npm.

## Decisions

### 1. Документы как файлы пакета с `go:embed`

`internal/help/docs/*.md` встраиваются через `//go:embed docs` в `internal/help`. Файлы версионируются и ревьюятся в PR вместе с кодом раздела.

Альтернатива: хранить справку в `docs/` в корне. Отвергнуто — `go:embed` не может брать родительский каталог, а копировать файлы при сборке усложняет процесс. Альтернатива: хранить в БД и редактировать в админке — отвергнута как лишняя CMS и источник рассинхронизации с кодом.

### 2. Реестр разделов в коде

Реестр — явная структура `id -> {Title, File, Roles}`. Идентификатор совпадает с путём SPA без слэша (`/tasks` -> `admin-tasks`, `/score-scales` -> `admin-score-scales`). Для `admin-users` и `admin-audit` список ролей ограничен администратором.

Альтернатива: выводить список разделов из маршрутов Vue или из файлов на диске. Отвергнуто — неявная связь, невозможно выразить права и заголовки; тест полноты становится сложнее.

### 3. Один эндпоинт `GET /api/help/:id`

Возвращает `{title, html}`. HTML готовит `markdown.Render`, поэтому клиент не рендерит Markdown сам и не нуждается в `marked` для справки. Маршрут регистрируется в группе с проверкой роли методиста/администратора; ограничение по ролям раздела проверяется в handler через реестр (для `users`/`audit` требуется `admin`). Неизвестный id — `404`, недоступный по роли — `403`.

Альтернатива: отдавать Markdown и рендерить в SPA через уже установленный `marked`. Отвергнуто — два рендерера и разная санитизация; серверный `markdown.Render` уже безопасен и единообразен с остальным контентом.

### 4. Один `<HelpButton>` в `App.vue`

Компонент монтируется над `<router-view/>` и берёт id раздела из `route.path`. Так кнопка появляется на всех экранах без правки `views/*.vue`, а реестр остаётся единственным источником правды. Окно — нативный `<dialog>` Pico, контент через `v-html` (HTML уже санитизирован на сервере). Ошибка загрузки показывается внутри окна.

Альтернатива: вставлять `<HelpButton id="..."/>` в каждый экран. Отвергнуто — 11 правок и риск забыть экран.

### 5. Тест полноты реестра

Table-driven тест проходит по реестру и проверяет: файл существует во встроенной ФС, документ непустой, заголовок задан, роли непустые, id уникальны. Тест — основной механизм «поддерживать в актуальном состоянии» на уровне CI; правила в `AGENTS.md` и ТЗ дополняют его для ревью.

## Risks / Trade-offs

- [Права на уровне раздела дублируются в реестре] → единственный источник — реестр; admin-only разделы проверяются по `Roles`, тест требует явных ролей для каждого id.
- [Справка может устареть по смыслу, оставаясь непустой] → тест ловит только отсутствие/пустоту; смысловую актуальность обеспечивают правила в `AGENTS.md` и Definition of Done.
- [`v-html` в SPA] → HTML санитизируется `markdown.Render` на сервере до отдачи; клиент не принимает произвольный HTML извне.
- [Рост `dist` при пересборке] → изменение аддитивное, размер меняется незначительно; сборка уже встроена в бинарь.

## Migration Plan

1. Добавить `internal/help` (реестр, сервис, handler, `docs/*.md`, тест).
2. Зарегистрировать `/api/help/:id` в `cmd/server/main.go`.
3. Добавить `HelpButton.vue`, смонтировать в `App.vue`, добавить стили диалога в `style.css`.
4. `npm run build` в `web/admin`; `go build ./...`.
5. Обновить ТЗ и `AGENTS.md` (правила актуальности).
6. Откат: удалить модуль, маршрут, компонент и стили, вернуть прежний `dist`, пересобрать SPA.
