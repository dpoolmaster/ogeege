## Why

Этап 1 дал аутентификацию, роли и профиль, но платформа всё ещё пуста: нет треков, структуры КИМ, тем, теории, заданий, вариантов, рубрик и шкал. Без управляемого контента нельзя запустить ни публичный банк заданий, ни диагностику, ни практику, ни пробники, поэтому этап 2 создаёт источник учебного контента и административный контур для его ведения методистом без участия разработчика.

Этап 2 из ТЗ (раздел 16, задачи 2.1–2.14) закрывает требования FR-CONT-01…10, FR-ADM-01…12, FR-IMP-01…07, QC-01…06, а также SEC-RBAC-01/05, SEC-AUD-01…04, SEC-WEB-02/04/07/08 и DATA-01…08. Он опирается на этап 1 (роли `methodist`/`admin` и middleware проверки прав) и снимает ограничение этапа 1: `exam_id` учебных целей начинает проверяться по реальному справочнику треков.

## What Changes

- Появляется модуль `content`: справочники треков и учебных лет, структура КИМ (номера, части, типы ответов, максимальные баллы), иерархия тем, теория в Markdown с версиями, банк заданий с `answer_spec`, варианты с позициями, рубрики части 2 и шкалы перевода первичного балла. Контент хранится в БД и меняется без правки кода.
- Вводится версионирование заданий и теории: изменение создаёт новую версию, прежние версии доступны администратору, задание, использованное в сессии, не удаляется, а архивируется.
- Появляется импорт заданий: создание черновиков из структурированного источника, проверка дубликатов по хешу нормализованного условия, ручное подтверждение и публикация только методистом. Импорт никогда не публикует автоматически.
- Появляется модуль `admin`: API `/api/admin/*` для управления контентом, пользователями и просмотра аудита, журнал аудита действий методиста и администратора, а также Vue SPA с Composition API, TipTap v3, KaTeX и highlight.js.
- Добавляется общий компонент `shared/storage` для загрузки изображений заданий в S3-совместимое хранилище с проверкой размера и типа и выдачей по серверному маршруту.
- Добавляется стартовый seed: треки `oge_math`, `ege_math_profile`, `ege_math_base` с примерной структурой КИМ и демонстрационным объёмом контента, достаточным для разработки следующих этапов.
- Учебные цели `profile` начинают проверять `exam_id` через интерфейс `content`: несуществующий или неопубликованный трек отклоняется.
- Добавляются миграции схем `content` и `admin` с UP и DOWN; схемы уже созданы на этапе 0, здесь появляются бизнес-таблицы.

Вне этапа: промпты и их тестовый запуск (FR-ADM-05, этап 7), очередь review (FR-ADM-06, этап 7), подписки и платежи (FR-ADM-08, этап 9), метрики (FR-ADM-10, этап 10), публичные страницы и открытый банк (этап 3), учебный цикл и снимки заданий в сессиях (этапы 4–6), AI-генерация контента (этап 7), полнотекстовый поиск и автоматический NLP-разбор условий.

## Capabilities

### New Capabilities

- `content`: справочники экзаменов и учебных лет, структура КИМ, иерархия тем, версионируемая теория, банк заданий с правилами проверки, конструктор вариантов, рубрики части 2, шкалы перевода, импорт и дедупликация, публикация и архивирование, стартовый seed.
- `admin`: серверный API администрирования для методиста и администратора, аудит действий, управление пользователями и ролями, разграничение прав методиста и администратора, Vue SPA для ведения контента с TipTap и KaTeX.

### Modified Capabilities

- `profile`: сохранение учебной цели дополнительно проверяет существование и опубликованность трека; несуществующий или неопубликованный `exam_id` отклоняется.

## Impact

- Новые Go-пакеты: `internal/content`, `internal/admin`, `internal/shared/storage`; сборка зависимостей между модулями только в `cmd/server/main.go`.
- Новые миграции: таблицы схем `content` (`exams`, `exam_years`, `kim_numbers`, `topics`, `kim_topics`, `theory`, `tasks`, `task_versions`, `task_options`, `task_attachments`, `variants`, `variant_tasks`, `rubrics`, `score_scales`) и `admin` (`audit_log`); без FK и JOIN между схемами, все ключи — UUID v7.
- Новые публичные контракты: JSON API `/api/admin/*` (раздел 8.9 ТЗ, расширенный недостающими методами CRUD), серверный маршрут выдачи изображений, SPA по `/admin`.
- Новые зависимости: клиент S3-совместимого хранилища и санитайзер Markdown/HTML; фронтенд — Vue 3, Vite, TipTap v3, KaTeX, highlight.js, Pico.css.
- Изменение контракта `profile`: `PUT /api/me/goals` возвращает ошибку валидации для несуществующего трека.
- Межмодульное взаимодействие: `admin` вызывает `content` и `auth` через интерфейсы, объявленные в `admin`; `profile` объявляет интерфейс проверки трека, который реализует `content`. Общих транзакций между схемами нет.
- Этап не меняет `docs/technical-specification.md` и `AGENTS.md` и не изменяет миграции этапов 0–1.
