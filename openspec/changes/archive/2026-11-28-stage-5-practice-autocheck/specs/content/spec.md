# content Specification

## ADDED Requirements

### Requirement: Варианты ответа задания

Система SHALL хранить варианты ответа задания с позицией, содержимым и признаком правильности. Варианты MUST создаваться и заменяться вместе с заданием, MUST сохранять заданный порядок и MUST NOT дублировать позицию. Для задания типа `choice` MUST быть не менее двух вариантов и хотя бы один правильный. Варианты MUST входить в снимок задания при старте сессии и MUST NOT изменять уже сохранённые сессии при последующем редактировании задания.

#### Scenario: Создание задания с вариантами

- **WHEN** методист создаёт задание типа `choice` с двумя и более вариантами и хотя бы одним правильным
- **THEN** задание и его варианты сохраняются, а варианты доступны для отображения и проверки

#### Scenario: Замена вариантов

- **WHEN** методист редактирует варианты задания
- **THEN** новый набор вариантов заменяет прежний, сохраняя порядок и не создавая дубликатов позиций

#### Scenario: Неполный набор вариантов

- **WHEN** для задания типа `choice` указан один вариант или ни одного правильного варианта
- **THEN** сохранение отклоняется с ошибкой валидации, а задание не меняется

#### Scenario: Снимок не меняется задним числом

- **WHEN** варианты задания изменяются после завершения сессии
- **THEN** снимок и результат этой сессии остаются прежними

### Requirement: Валидация правил проверки по реестру

Система SHALL валидировать `answer_spec` по типу через единый реестр стратегий. Неизвестный `kind` MUST отклоняться. Обязательные поля типа MUST проверяться. Для `choice` каждый правильный идентификатор MUST существовать среди вариантов задания. Ошибка MUST возвращаться с понятным сообщением, а задание MUST NOT сохраняться в невалидном виде.

#### Scenario: Корректные правила

- **WHEN** методист сохраняет задание с корректным `answer_spec` известного типа
- **THEN** задание сохраняется

#### Scenario: Неизвестный тип

- **WHEN** методист сохраняет задание с неизвестным `answer_spec.kind`
- **THEN** сохранение отклоняется с понятной ошибкой

#### Scenario: Ссылка на отсутствующий вариант

- **WHEN** `choice` ссылается на вариант, которого нет среди вариантов задания
- **THEN** сохранение отклоняется, а прежняя версия задания остаётся без изменений

#### Scenario: Некорректное обязательное поле

- **WHEN** `answer_spec` не содержит обязательного поля своего типа или содержит недопустимое значение
- **THEN** сохранение отклоняется с ошибкой валидации

### Requirement: Импорт вариантов ответа

Система SHALL поддерживать импорт вариантов ответа вместе с заданием. При импорте MUST проверяться уникальность позиций и соответствие `answer_spec` вариантам. Дубликаты позиций и ссылки на отсутствующие варианты MUST отклоняться без частичного сохранения задания.

#### Scenario: Импорт задания с вариантами

- **WHEN** импортируется задание типа `choice` с корректным набором вариантов и правил проверки
- **THEN** задание и варианты сохраняются как черновик

#### Scenario: Дубликат позиции

- **WHEN** импортируемое задание содержит два варианта с одинаковой позицией
- **THEN** импорт отклоняется, а задание не сохраняется частично

#### Scenario: Несоответствие правил и вариантов

- **WHEN** импортируемое задание типа `choice` ссылается на вариант, которого нет в импортируемом наборе
- **THEN** импорт отклоняется с понятной ошибкой
