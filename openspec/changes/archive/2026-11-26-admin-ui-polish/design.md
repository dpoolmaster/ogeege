## Context

См. `proposal.md` — Why. Админка собрана на Vue 3 + Vite + Pico.css. Pico подключается первым в `web/admin/src/main.js`, затем идёт `./style.css`, поэтому собственные правила при равной специфичности перекрывают Pico.

Текущий каркас (`web/admin/src/App.vue`): grid из двух колонок `220px 1fr`, слева `<nav class="admin-nav">` с прямыми `<router-link>`, справа `<main class="admin-content">`. Одиннадцать экранов в `web/admin/src/views/` используют общий шаблон `h2 -> .admin-form -> table`; секционные `h3` есть только в `TasksView.vue`.

Источники «нелепости» подтверждены в исходнике Pico:

- `--pico-font-size` растёт до 131.25% на широких экранах (root ~21px), остальное в `rem`.
- `nav` по умолчанию `display: flex; justify-content: space-between`, поэтому прямые дети-ссылки выстраиваются в ряд и сжимаются в 220px.
- `input/select/textarea` имеют `margin-bottom: var(--pico-spacing)` и padding `0.75rem`, а `.admin-form` дополнительно задаёт grid-gap и `align-items: end`.

## Goals / Non-Goals

**Goals:**

- Зафиксировать базовый шрифт 14px и плотный вертикальный ритм.
- Дать понятный каркас: верхняя панель + вертикальная липкая навигация + контент.
- Устранить двойные отступы и «наезды» заголовков, выровнять кнопки форм.
- Сохранить текущую структуру экранов: правки минимальны, без переписывания `views/*`.
- Сборка остаётся встроенной в Go-бинарь без изменений в Go-коде.

**Non-Goals:**

- Не менять API, маршруты, права, данные и обработку ошибок.
- Не вводить UI-фреймворк/дизайн-систему сверх Pico.
- Не переделывать экраны по одному и не добавлять новые функции (фильтры, модалки).
- Не менять `Editor.vue` логику TipTap/KaTeX — только визуальное окружение.

## Decisions

### 1. Переопределение токенов Pico вместо форка/замены CSS

В `style.css` на `:root` задаём базовые переменные Pico: `--pico-font-size: 87.5%` (14px), `--pico-spacing: .65rem`, `--pico-form-element-spacing-vertical: .35rem`, `--pico-form-element-spacing-horizontal: .55rem`, `--pico-typography-spacing-vertical: .5rem`, `--pico-typography-spacing-top: .75rem`.

Альтернатива: подключить `pico.fluid.*` или вручную править исходник Pico. Отвергнуто — fluid и есть причина раздувания, а форк усложняет обновления.

### 2. Каркас: `<header>` + боковая навигация списком

`App.vue` получает `<header class="admin-topbar">` (бренд, email/роль, кнопка «Выйти» → `POST /api/auth/logout` с CSRF или переход на `/logout`), а навигация становится `<ul><li><router-link>`.

```
+--------------------------------------------------------------+
| header: Админка .......... user@mail (role)   [Выйти]         |
+----------------+---------------------------------------------+
| nav (sticky)   | main                                         |
|  Треки    *    |  h2 + форма-фильтр + форма + таблица         |
|  ...           |                                              |
+----------------+---------------------------------------------+
```

`nav` получает `flex-direction: column`, `position: sticky; top: 0; height: 100vh`, `overflow: auto`; активный пункт — `.router-link-active`. На узких экранах (<900px) каркас становится одноколоночным, навигация — горизонтальной прокручиваемой полосой.

Альтернатива: оставить прямые ссылки и просто поправить `flex-wrap`. Отвергнуто — не решает липкость и активный раздел, семантика списка лучше.

### 3. Формы и таблицы

В `.admin-form` убираем `align-items: end` в пользу `align-items: start`, у полей и кнопок внутри формы `margin-bottom: 0`, кнопки — `align-self: end`. Таблицы делаем компактнее (`font-size: .9rem`, меньше padding у ячеек). Заголовки `h2`/`h3` получают явные размеры (`1.25rem`/`1rem`) и малые отступы.

Альтернатива: править каждый `views/*.vue`. Отвергнуто — правки общие и покрываются CSS; экраны трогаем только если понадобится.

### 4. Пересборка и встраивание

После правок `npm run build` в `web/admin` перезаписывает `dist`, который через `//go:embed dist` попадает в бинарь. Go-код не меняется.

## Risks / Trade-offs

- [Специфичность: правила Pico могут перебить наши] → `style.css` грузится после Pico; при конфликте повышаем специфичность селектором `.admin-content`/`.admin-nav`.
- [Sticky-навигация с `height: 100vh` может обрезать длинные меню] → `overflow: auto`; на мобильных отключаем sticky.
- [Кнопка «Выйти» требует CSRF] → используем существующий `POST /api/auth/logout` через `api()` (он уже шлёт `X-CSRF-Token`) либо обычный переход на `/logout`.
- [Фиксированные 14px могут мелковато выглядеть на HiDPI] → базовый размер вынесен в одну переменную, легко поднять до 15px.

## Migration Plan

1. Переписать `web/admin/src/style.css`.
2. Обновить `web/admin/src/App.vue` (header + nav-список).
3. `npm run build` в `web/admin`; при необходимости `templ generate` не требуется.
4. `go build ./...` — проверить, что `go:embed` подхватил новый `dist`.
5. Откат: вернуть прежние `style.css`/`App.vue` и пересобрать SPA.
